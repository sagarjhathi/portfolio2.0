YouTube Language Validator

The YouTube multi-language checks from my Java project, ported to Playwright and TypeScript. It switches YouTube’s language and region again and again, then checks that the interface really shows the expected language.

01. Overview

The tests run against the live youtube.com, signed out, in a real browser. Nothing is mocked. For each language row they select the language, wait for the reload, read the UI element under test, and compare it with expected data or detect its language. The 8 checks cover:

  • The side menu, both expanded and collapsed
  • The settings menu
  • The country code on the YouTube logo for each region
  • The search-filter popup
8checks across the menus, settings, logo and filter popup
4parallel CI shards with merged reports
2verification styles: exact text and language detection
3published outputs: landing page, Playwright report and Allure

02. What makes it special

Intelligence

Two ways to verify

Exact text matching against expected data, plus language detection with the eld library. Tests whose names end in “Lingua” use detection.

Assertions

All wrong languages in one run

Soft assertions report a wrong language at the end of the run and let the loop keep going through the remaining languages.

Reliability

SafeActions helper

Waits until an element is visible and enabled, retries up to three times, refreshes the page between later attempts, and falls back to a DOM click before it fails with a clear error.

Data

JSON-driven expectations

Expected values live in one JSON file per check, and run size is set in runconfig.json. Environment variables override the file.

CI

Sharded nightly runs

CI splits the tests into 4 shards, merges the blob reports into one HTML report, and combines the Allure results. A nightly run sets IS_CRON to switch to the wider config.

Reporting

Reports on GitHub Pages

Each run publishes a landing page with the run number and commit, the merged Playwright report, and an Allure report that keeps its history for trend graphs.

Navigation

Handles the page reload

Language clicks use a DOM click so Playwright does not wait on the navigation the click itself starts, which keeps language loops from stalling.

Honesty

Knows detection’s limits

The spec skips full detection for the few languages eld cannot handle and checks the <html lang> value instead.

03. Architecture

Each layer builds on the one below it.

  1. testsYtMasterSafeActions.spec.ts is the maintained suite. YtMaster.spec.ts is the original, plain Playwright version.
  2. pagesYtLandingPage holds the locators and page methods.
  3. utilsSafeActions, GenericUtility (html lang checks, screenshots, iteration counts) and ReadJSON.
  4. detectionlanguageDetector built on eld, used by the “Lingua” tests.
  5. configs & datarunconfig.json plus one JSON file of expected results per check.

04. CI pipeline

Keys in the run config that end in CI apply to scheduled runs, so the same code covers a quick push and a thorough night.

  1. 1 · Trigger

    Push or pull request to main or master, a manual run, or nightly at 20:00 UTC (01:30 IST).

  2. 2 · Configure

    The nightly run sets IS_CRON=true so the tests read the scheduled config.

  3. 3 · Test

    4 shards, each uploading a blob report and Allure results. One retry on CI.

    shard 1/4shard 2/4shard 3/4shard 4/4

  4. 4 · Merge

    One Playwright HTML report, and one Allure report built from every shard.

  5. 5 · Publish

    Pushes, manual and nightly runs deploy to GitHub Pages. Pull requests only build.

Tier 2 What makes it smart

eld

Language detection

Detects the language of the UI text that was actually rendered, instead of trusting the setting that was clicked.

SafeActions

Resilience helper

Visible-and-enabled waits, three attempts, page refreshes and a DOM-click fallback for flaky interactions.

JSON data + RunConfig

Data and configuration

Expected results per check, run-size switches, and environment variable overrides.

Tier 3 Reporting

Playwright HTML report

Debugging

Merged from all four shards into one report you can open with show-report.

Allure

Trends

Results from every shard combined, with the previous history copied in so trend graphs continue.

Soft assertions

Result quality

A wrong language is recorded and the loop continues, so one run lists every problem.

Tier 4 Delivery

GitHub Actions

CI/CD

Four-shard matrix, a nightly cron and a merge job that needs write permission to publish.

GitHub Pages

Hosting

A gh-pages branch with the landing page, Allure and Playwright reports, replaced by a single commit each time.

Environment overrides

Run control

IS_CRON and other variables switch the config without editing a file.
