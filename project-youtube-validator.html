YouTube Language Validator
Java + Selenium

A framework that checks whether YouTube really shows the right language and region settings across 40+ locales. It does not just compare text. It detects the language of what is on screen, and checks that the page’s language tag agrees.

01. Overview

For each language and region, the framework applies the setting in a real browser, reads the text that YouTube renders, and verifies:

  • The side menu language, both expanded and collapsed, against the settings
  • The settings menu localization
  • Filter labels on the search results page
  • The <html lang> attribute
  • The country code shown on the YouTube logo for each region
  • UI stability across screen sizes and layouts
40+languages and regions validated

3signals cross-checked: text, detected language, html lang

02. What makes it special

Intelligence

Detects the real language

The Lingua library identifies the language of the text on screen. This catches mixed languages and half-translated pages that a plain string match would miss.

Validation

Cross-checks three sources

The visible text, the detected language and the page’s html lang tag must all agree, so one wrong signal cannot hide a localization bug.

Data

Expectation matrices in Excel

Expected values per language and per country-to-locale change live in Excel files. New languages are added by editing data, not code.

CI

Coverage that follows the trigger

Pushes and pull requests run a reduced set of languages for fast feedback. The nightly run covers every language and region.

Reliability

Built for a dynamic app

YouTube is a single-page app that changes constantly. SafeActions adds retries, a JavaScript click fallback and page-refresh recovery to keep runs stable.

Structure

Split by intent

Tests are tagged into lingua and non-lingua groups that run as separate parallel shards, so detection-heavy tests do not slow the rest.

Locale

Region and country checks

A dedicated test maps each region to the country code shown on the YouTube logo, so location settings are verified as well as language.

Evidence

Easy to debug

Each run has its own folder, each test its own log, and screenshots are embedded in the Extent report published to GitHub Pages.

03. Architecture

Each layer builds on the one below it.

  1. TestsTestNG tests (YtMasterTests) with retry analyzers and suite-based runs.
  2. BaseTestShared setup, driver lifecycle and the reporting listener.
  3. Page objectsYtLandingPage and YtInnerPage describe the YouTube surfaces.
  4. SafeActionsThe resilience layer: retries, waits, JavaScript click fallback and refresh recovery.
  5. Driver & utilitiesDriverManager, ConfigManager, WaitUtility, GenericUtility and ScreenshotUtil.
  6. LinguaLanguage detection on the extracted UI text.
  7. Logging & reportingLog4j2 routing logs, Extent Spark reports and Allure results.

04. CI pipeline

One workflow runs the two test groups in parallel and publishes a single report hub.

  1. 1 · Trigger

    Push, pull request, manual run or nightly CRON.

  2. 2 · Choose coverage

    Reduced languages for pushes and pull requests. Every language and region at night.

  3. 3 · Parallel shards

    Each shard runs a tagged group and stores its Extent run folder and Allure results.

    linguanon-lingua

  4. 4 · Publish

    Merges Allure into one dashboard and deploys the hub with both Extent reports.

  5. 5 · Notify

    Discord messages at start and finish, with report links.

Known limits: YouTube changes its UI without notice, so a failure can be a layout change, an experiment or a CAPTCHA rather than a localization bug. Detection is probabilistic, and results vary by IP region, cookies and consent dialogs. For learning and QA research only, not affiliated with YouTube or Google.
